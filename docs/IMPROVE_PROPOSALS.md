## P0-1. 네트워크·서비스 계층 (REST/메시징/DB/인증) — 설계결정 필요 → 미구현

**왜 제안만**: 인증·인가·상태영속성(DB)·푸시 전달은 명시적 비구현 범위(야간 작업 지침). 검증 불가한 신규 서버 코드를 무인으로 쌓지 않음.

| 옵션 | 장점 | 단점 | 적합 |
|---|---|---|---|
| **A. FastAPI + REST(동기)** | 빠른 프로토타이핑, OpenAPI 자동문서, `Receipt`/`Record`/`Alert` dataclass→Pydantic 직매핑 | 실시간 경보는 폴링/SSE 별도, 엣지 다수 연결 시 비효율 | 앱↔백엔드 정산·조회 |
| **B. MQTT(메시징)** | 엣지(카스토퍼) 다수 ↔ 백엔드 비동기, 경보 push 자연스러움 | 브로커 운영·QoS·보안 설계 추가, 요청응답형 조회엔 부적합 | 엣지→백엔드 이벤트/경보 스트림 |
| **C. 하이브리드(REST 조회 + MQTT 이벤트)** | 조회·정산은 REST, 실시간 경보·점유는 MQTT — 역할 분리 | 두 스택 운영 복잡도 | 제품 단계 권장 출발점 |

**선결 결정**: 인증 방식(앱 JWT vs 디바이스 mTLS), DB(시계열 점유 vs 관계형 원장), `spot`·절대시각 부여(아래 P1-5와 연동). 출발점은 [API_CONTRACTS.md](API_CONTRACTS.md) §2.

## P1-1. INT8 vs FP32 — 엣지 디바이스 선정 의존 → 미구현

**측정 사실**(records/02·04): 정적 INT8 36.5ms > ONNX-FP32 14.1ms(VNNI/NPU 없는 데스크톱), 크기 3.4MB(7.2×↓).

- **지연 최적이면 → FP32**(현 데스크톱급 CPU에서 더 빠름).
- **크기/대역폭 최적이면 → INT8**(저장·전송 7.2×↓).
- **NPU/VNNI 타깃이면 → 재양자화**(TFLite/NNAPI 또는 TensorRT). 현 ONNX 정적 INT8은 해당 가속기에서 역전될 수 있음 — **타깃 디바이스 실측 후 결정**.

본 작업 미구현 이유: 타깃 하드웨어 미정 → 어느 쪽도 "정답"으로 고정 불가.

## P1-2. ③ 세부 날씨분류 실-전이 — 실 라벨셋 필요 → 미구현

**사실**(records/04, BDD100K 1,053장): **야간/저조도 0.99 실전이 ✅**(휘도=물리적). 비·눈 등 외형 날씨피처 **실 미전이**(전이 acc 0.36). `streak_coh` 실 주간 도로질감 과발화, `speckle` 실 적설 미발화.

**제안(데이터 확보 시)**: 실 외형정합 라벨셋(CCPD/실 CCTV 악천후) 확보 후 비·눈 피처 재보정 또는 재학습. **단기 운영 정책**: 저조도 게이팅(실 유효)만 활성, 비/눈 세부분류는 "신호"로만 — 결정에 직접 사용 금지.

## P1-3. ② 이상탐지 정밀도-재현율 — 운영정책 결정 → 미구현

**사실**: 실 점유×원장 공개셋 부재. 룰+IF 켜면 정밀도 1.0→0.81, 전체 F1은 룰만(0.970)이 더 높음.

| 정책 | 결과 | 적합 |
|---|---|---|
| **룰=결정, ML=2차 검토 신호**(현 권장) | 정밀도 보존(오탐 억제), subtle 고장은 검토 큐로 | 과태료 등 오탐 비용 큰 운영 |
| **룰+ML 모두 결정** | 재현율↑(subtle 포착) 정밀도↓(0.81) | 누락 비용이 오탐 비용보다 큰 경우 |

**미구현 이유**: 오탐/누락 비용은 운영 정책(과태료 처리 방식)에 의존. 실 점유/원장 확보 시 재검증 필요.

## P1-5. API 계약상 운영 공백 — 백엔드 규약 수립 필요 → 미구현

**코드 실측 공백**:
1. `Record`에 `spot`·절대시각 없음(단일 카스토퍼·분단위 시뮬 전제). `Event`/`Receipt`엔 `spot` 있음.
2. 번호판 미인식 표현 혼재: `Record.plate=None` vs `Receipt.plate="미인식"`.
3. 시간 단위 전부 '분'(float) — 절대 타임스탬프 변환 규약 없음.

**제안(택1 후 통일)**:
- **null 표현**: 전 계층 `None`(타입 명확) **또는** 표시문자열은 프론트에서만 변환. → 백엔드 경계에선 `None` 권장, 표시는 UI 책임.
- **spot/절대시각**: 입차 이벤트에 디바이스ID→spot 매핑 + 분단위 오프셋→UTC 변환을 API 진입점에서 부여. → [API_CONTRACTS.md](API_CONTRACTS.md) §2.4.

**미구현 이유**: 표현 통일은 앱↔백엔드 계약 동시 변경이라 단독 변경 시 회귀 위험. 양측 합의 후 일괄 적용 권장.
